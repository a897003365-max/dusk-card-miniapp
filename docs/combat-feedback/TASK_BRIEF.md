# 本轮战斗反馈修订

用户要求修复手机扫码预览无声，增加 Boss 攻击特效，使单体/群体目标和掉血清楚。交付载体是已存在的原生微信小程序可编辑源码及原生截图/短视频，不新增 HTML 或 Figma 产品，不生成新角色图片。

保留已确定的纸灵驿使、三处旧街邮路、原有角色与 Boss 形象。此次为现有反馈修订，实施细节由任务授权执行；此记录不宣称新增视觉方向已经用户批准。

玩家在320/390/430宽屏先识别谁在行动，再识别受影响目标，再读出实际生命损失和护盾抵消。数字与目标只能来自已结算事件；单体/全体取规则元数据，不能由存活目标数量猜测。声音开关表达用户播放意图，试听成功仅表示收到播放回调，不能代替手机实际听感。

参考当前项目源码和上一轮原生截图作为项目证据，使用 Victor Product UI 的状态、反馈、恢复与可读性审查。原有纸张/墨/铜铃材质是当前主题依据，红色负数对应生命损失、蓝色盾对应格挡、绿色正数对应治疗；界面用现有字体。拒绝无来源的全屏闪光和同时播放所有敌人造成的伤害混淆。

本轮四个主要设计动作是逐敌施招与命中节拍、明确单体/全体范围、对应目标标记、分开显示掉血/治疗/格挡；三位 Boss 分别使用纸刃、墨浪、铃环。实际图片只用现有本土化资产，几何特效用于表达攻击路径和范围。色彩、粒子与文字都服务这些动作，不加无关装饰。

动画开始前状态只提交一次。关闭、切后台或保存失败不补播成功反馈。需检查普通攻击、Boss单体、Boss群体、格挡、治疗、倒下/阶段转换及320宽度，并保留失败日志。

## 2026-09-12 · Boss 节奏与战后回执修订

用户要求延长 Boss 特效，并让战斗结算有明确仪式。载体、主题和素材边界保持不变：继续使用原生微信小程序、现有纸灵角色、旧街背景、纸张与邮戳语汇；不生成新角色；本节聚焦表现，新卡机制另见冒险模块契约。玩家先读 Boss 蓄势，再读命中与实际数字，最后留出空场间歇。Boss 的阶段元数据固定为蓄势 800ms、命中读数 1200ms、间歇 300ms；普通敌人与旅伴保留现有短节拍。CSS 动画时长跟随这三段固定元数据，单次结束，不用反复抖动表达强度。

战斗胜利、精英胜利、最终 Boss 胜利和失败都进入同一张战后回执状态。四种状态共享纸张展开、地点与难度、邮戳、队伍、真实收益和底部确认；邮戳文案分别承担本站、要件、全程送达与归队的结果识别。普通与精英回执由玩家点“查看战利品”进入已经保存的选牌或旧物奖励；最终胜利与失败由玩家点“收好回执”返回邮局。确认前不自动消失。

回执只读取已经提交的 `run` / `lastResult` 和本次事件：即时战斗展示本次 `reward` 金额、真实回合和队伍；重新进入旧的最终回执时，旧存档没有队伍与回合快照就不展示这些字段。累计星线明确写作“本程已入库”，最终邮票取 `lastResult.tickets`。宝箱进入 `relicReward` 时节点类型为 `treasure`，不得生成精英战胜回执。保存失败不生成回执；切后台取消尚未完成的特效，并从已存 `reward/result` 恢复确认层，不重复提交奖励。

修订审查保留现有画面的纸墨层次和手机声音路径，移除持续来回的单位状态摆动。主状态至少有四个有因动作：Boss 阶段标签、命中读数停留、纸张展开、邮戳落定；回执再以约 650ms 的队伍行和约 950ms 的收益行依次显现，完整仪式约 1.4 秒，确认按钮始终可用。320 短屏由回执正文滚动，确认区固定，按钮最小高度 44px；减少动效时所有文案、结果和操作仍直接可读。

原生截图复核发现微信默认 mini 按钮样式撑高蓄能栏，以及回执邮戳与标题重叠。本轮为工具条按钮增加容器选择器并明确44px高度；邮戳预留100px独立区域（包含旋转后的实际边界），标题从其下开始。新蓄能HUD同时显示本回合出牌数，点击直达说明；消耗/保留卡增加“耗/留”标签，减费卡详情同时列出原费用。
