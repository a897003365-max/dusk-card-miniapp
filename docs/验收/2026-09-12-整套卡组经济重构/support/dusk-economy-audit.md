# 《晚霞来信》卡组与费用体系只读审查

审查范围：`utils/combat-content.js` 全部 74 张牌（44 专属、30 通用）、22 个伙伴被动、18 件遗物、21 个敌人、3 套起手战术、3 区域 × 3 难度；`utils/combat.js` 完整结算；`utils/status-help.js`；`docs/adventure/CONTRACT.md`、`TASK_BRIEF.md`；`tests/combat-content.test.js`、`tests/combat.test.js`、`tests/helpers/adventure-policy.js` 与说明；另核对了 UI 对 `previewAction` 的使用。未修改项目源码。

## 结论

当前系统在“规则能执行、存档边界完整、所有内容可触发”方面扎实，但尚未形成成熟牌组构筑游戏所需的费用曲线、机会成本和构筑闭环。核心不是若干牌差 1–2 点数值，而是 74 张牌的 70.3% 都挤在 1 费，45/52 张 1 费牌同时塞入两个或三个效果；4 费终结依赖一个稀薄、与奖励不成套的蓄能子系统。0 费牌虽然不存在已经证实的无限循环，却仍主要是免费小伤害、小盾和小状态，并通过“第三张牌”、按出牌触发的被动/遗物获得额外价值，和用户想要的环境改变、状态转换、未知机会不是同一设计方向。

## 费用曲线与高费可达性

- 费用分布：0 费 9 张，1 费 52 张，2 费 9 张，3 费 1 张，4 费 3 张。1 费占 70.3%，3–4 费合计仅 4 张且全部是战术牌。曲线没有中费桥梁，普通牌的选择常变成“哪个 1 费套餐塞的效果更多”。
- 每回合开始直接把能量设回 3（`utils/combat.js:349-354`）；4 费牌在 0 蓄能时绝对不可打。未用能量不能保留，也不会自动转成蓄能。
- 复杂起手各只有一张可循环蓄能源：`relay` 的 `wind-up-stamp`、`reserve` 的 `dusk-ledger`，以及各一张 4 费终结。12 张牌抽 5 张时，蓄能源与终结首手同时出现的理论/实测比例约 15.2%。
- 10,000 个 seed 的实现级资源探针（只在真实 resolver 中打蓄能源、保留终结，不按伤害挑牌；把队伍生命抬高以隔离抽牌/能量可达性，不把它作为胜率）显示：`express-finale` 可打回合中位数 3、P90 为 4；`lantern-storm` 同样中位数 3、P90 为 4。第 2 回合前可打比例分别 34.6% / 38.3%，第 3 回合前均 83.6%。这说明“保留”解决了丢牌，没有解决等待与占手。
- 最早同手抽到蓄能源和终结也不能当回合打：先付 1 能量获得 1 蓄能后，4 费降为 3，但只剩 2 能量，只能等下一回合。
- `sealed-route` 是唯一 3 费牌，12 点追加伤害又要求它是本回合第 3 张。0 蓄能时，必须先打两张总净费用为 0 的牌才能触发追加；普通两张 1 费铺垫后只剩 1 能量，牌根本打不出去。牌面条件和费用系统互相打架。
- 三张 4 费牌的收益口径不一致：`express-finale` 是单体 26；`night-shelter` 是全队 10 盾和留盾（单次总量最多 30）；`lantern-storm` 对每敌人施加 6 灼烧和 2 标记，单体满持续价值可达 21 点无视护盾灼烧再加最多 4 点标记，三目标时近似三倍。相同费用不能代表相近收益。

## 资源闭环

- 蓄能源仅 5 张：`loose-thread`、`thermos-pause`、`wind-up-stamp`、`dusk-ledger`、`relay-mark`；蓄能消费者仅 4 张：`night-shelter`、`sealed-route`、`express-finale`、`lantern-storm`。18 件遗物没有一件与蓄能交互。
- 普通战奖励按路线流派固定塞入一张随机战术牌，但不检查当前牌组是否已有源或消费者。因此会给出没有终结的蓄能牌，也会给出没有蓄能源的 4 费死牌。玩家可以跳过，只是这会让“每组必含战术牌”的槽位成为伪选择。
- 奖励不排除已拥有卡，同一 0 费/蓄能/终结可重复加入。牌组只能从 12 加到最多 16，没有删牌/变形机制；弱起始牌被更强牌严格盖过后仍永久稀释抽牌。
- `borrowed-step` 是全库唯一直接产能卡：1 费、返 1 能量且不消耗，实际净 0 费并提供 3 盾、计入出牌数、触发护盾类被动/遗物。结构测试只检查“产能量 <= 卡牌费用”，因此正好放过这张可反复回洗的零净费发动机。
- `soup` 被动使每回合第一张治疗牌返 1 能量；引擎即使实际治疗为 0 也把 `facts.heal` 置真。于是满血时 `soup-ladle` 仍可净 0 费获得 3 盾，`soup-steam` 仍可净 0 费给全体敌人虚弱并尝试全队治疗。这未必是无限循环，却显著改变费用口径。
- `rush-stamp` 在每回合第 3 张牌返 1 能量；`ticket-punch` 在第一张伤害牌后抽 1；`folded-map` 在首次标记后抽 1。0 费牌既计连锁又能触发这些收益，因此其真实价值远高于牌面的小伤害/小盾。

## 0 费与免费循环风险

- 9 张 0 费中，5 张非消耗：`badminton-drop`（2 伤+虚弱）、`firefly-flash`（标记+2 盾）、`folded-corner`（3 盾）、`paper-dart`（3 伤）、`address-label`（标记）；4 张消耗战术是蓄能、条件反击、抽牌、条件灼烧。
- 当前没有发现真正无限循环：所有 0 费抽牌/补能/蓄能都带消耗，非消耗 0 费牌不抽牌；直接能量卡也不抽牌。这个防线是有效的。
- 现有测试“不能形成无限循环”只打一张 `quick-sketch` 并确认它移除，证明单卡不会自循环，没有覆盖组合循环、重复奖励、净零能量牌、按第三张触发的产能遗物和治疗返能被动。
- 更现实的风险是免费动作泛滥：非消耗 0 费牌在回洗后持续充当第三张启动器，让 `thirdPlay` 被动/遗物稳定触发；它们的真实价值来自免费触发系统，而非牌面收益。重复奖励会放大此问题。
- 当前 12 种效果原语没有环境、姿态、意图改写、牌序选择、临时牌发现或状态转换，所以仅调小伤害/护盾无法满足“0 费改变环境/状态/创造未知机会”。需要新增至少一个战场状态和一个受控发现/变形原语，不能继续用数值效果换皮。

## 明确支配与数值异常

以下为基础牌在相同费用、相同目标语义下的首用 Pareto 支配；专属牌只有对应伙伴在队时才进入池，消耗牌另有一次性代价：

- `wax-impression` 比 `sunset-glow` 多 1 虚弱，其余同为 1 费、单敌、2 灼烧+2 标记；升级后仍完整支配。
- `blanket-quilt` 比 `nav-compass` 多 1 盾和 1 留盾，其余同为 1 费、自身、1 回响；升级后仍完整支配。
- `ticket-cut` 与 `orangecat-sidestep` 都是 1 费、单敌、5 伤+抽 1，前者额外虚弱 1；升级也同为 8 伤+抽 1，仍多虚弱。
- `cloudmail-stamp` 的标记先结算，基础实际为 10 直接伤害；`orangecat-pounce` 仅 8，且二者同为 1 费双段单体。`badminton-rally` 是 9 点三段；这些牌没有形成清晰的多段代价。
- `firefly-trail`（先 2 标记再 6 伤）当场造成 8 并留下 1 标记，完整盖过 `stamped-route`（先 4 伤后留 1 标记）。
- `soup-ladle`（7 治疗+3 盾）完整盖过通用 `packed-lunch`（6 治疗）；升级仍为 10+4 对 9。
- `soup-steam`（全敌虚弱 1+全队治疗 2）完整盖过 `quiet-bell`（全敌虚弱 1）；升级仍完整盖过。
- `firefly-flash`（0 费标记 1+盾 2、不消耗）完整盖过 `address-label`（0 费标记 1、不消耗）。
- `catcafe-night` 基础为抽 2+治疗 2，完整盖过 `margin-notes` 的抽 2；升级后后者抽 3，才重新形成取舍。
- 基础 `strike`/`guard` 被大量 1 费牌严格盖过，本可作为构筑游戏的待替换弱牌；但当前没有删牌、变牌或换牌，只能升级或继续加牌，因此弱起手只制造永久抽牌税。
- 59/74 张牌含至少两个效果，11 张含三个效果；52 张 1 费牌里 45 张含至少两个效果。组合套餐过密，使“付费对应一种主要收益、附带一个可读条件”的费用语言失效。
- 灼烧明显优于同费直接伤害：`ink-drop` 1 费施加 4 灼烧，若目标存活可造成 4+3+2+1=10 点无视护盾伤害，基础 `strike` 是 6；升级 6 灼烧总潜力 21，而 `strike+` 是 9。高难度的固定护甲进一步抬高灼烧相对价值。
- 全体效果按目标数线性放大但费用不变。`cloudmail-express` 1 费对每敌 4 伤并抽 1，`hydrangea-pollen` 1 费对每敌 2 标记+虚弱，`soup-steam` 同时覆盖全敌和全队。大多数战斗单敌、灯市 Boss 会召唤至 3 敌，使同一牌跨区域价值可放大约三倍，奖励却不按区域/敌群校准。

## 22 被动与 18 遗物

- 数量、触发时机和签名均完整，测试覆盖“能触发”，没有覆盖相对价值、触发概率和死触发。
- 抽牌/能量类在同样“一回合一次”下通常支配小额伤害/治疗类，因为它们既提高本回合选择，又启动更多出牌触发。`ticket-punch`（每回合首次伤害抽 1）和 `rush-stamp`（第三张返 1 能量）会放大 0 费；现有遗物偏好列表也优先选择这两件，说明测试策略事实上承认资源遗物更强。
- `night-bookmark` 和 `catcafe` 被动都只在每场战斗第一次回合开始抽 1，而 `folded-map`/`nav` 可在每回合首次标记时抽 1。后者在带标记牌时上限明显更高，缺少相应触发难度或数值补偿。
- 全队效果和自身效果使用同一原始数值：`smooth-pebble` 每回合全队各 2 盾（最多总 6），`tea-token` 每回合只给当前默认自身治疗 2；`warm-handkerchief` 每回合首次治疗后全队各 3 盾（总 9）。遗物之间不是同一价值带。
- 触发效果的敌方目标若原牌没有单体 `targetId`，引擎自动落到第一个存活敌人。群攻/自保牌触发 `enemy` 被动或遗物时，玩家无法选落点，是隐藏的自动决策。

## 三套起手与三区三难度

- `classic` 是 3 张 6 伤起手；`relay` 用 0 费抽 1 消耗、1 费 4 伤+蓄能、4 费 26 伤保留替换三张攻击；`reserve` 用 0 费标记/条件灼烧消耗、1 费抽 1+蓄能、4 费全体灼烧/标记保留替换。后两套把即时稳定的 18 伤改成依赖抽序、跨回合和持牌者存活的组合，却没有显示“预计启动回合”或首战容错。
- 战术牌按队伍顺序分配持有者。第三位持有 4 费终结，第三位一旦倒下，该牌会随其全部牌本战移除；复杂起手因此还隐含队伍排序与生存风险。
- 区域基础生命：街/桥/市普通怪均值 34 / 27.5 / 30.5，精英均值 40 / 50.5 / 56，Boss 两阶段总血 100 / 128 / 146。桥、市普通战反而更轻，精英突然较街区增加约 26% / 40%，Boss 增加 28% / 46%；灯市 Boss 还召唤小怪。这是明显的关底台阶，不是平滑的区域学习曲线。
- 三难度统一把敌血乘 1 / 1.18 / 1.4、主动攻击乘 1 / 1.15 / 1.3；险路/深夜另在每次敌行动前加 2 盾，深夜每第三回合攻击再 +2。2 盾对低伤免费牌影响大，灼烧完全绕过，进一步收窄高难可行构筑。
- Boss 转阶段清空自身全部状态。状态流派在临界点投入的未结算灼烧、标记、虚弱全部作废，而直接伤害没有同类损耗；牌面和起手战术没有提醒这项流派税。
- 已有自然成长记录本身显示：同一策略在夜行灯市以 3/3/3、3/3/4、3/4/4 连续三次失败，到 4/4/4 才通关。它是一个具体压力信号，但仍只是单策略/少量 seed，不能单独证明数值结论。

## 抽牌预览与信息泄漏

- 当前玩家 UI 没有泄漏下一张牌身份。`previewAction` 返回事件和摘要，不返回演算后的 state；`getAdventureView` 只暴露抽牌堆数量，不暴露 `drawPile` 顺序；牌组页的 `deck` 是卡实例清单，不是抽牌顺序。
- 纯 JS 对照探针把隐藏抽牌堆完全反转：`quick-note` 的两份预览仍逐字相同（仅“抽取 2 张牌”），实际执行后抽到的 UID 不同。这说明当前预览边界正确。
- `getAdventureView` 会用 `previewAction(endTurn)` 完整演算敌方行动，因此公开的是按当前状态计算后的精确意图、伤害、目标和护盾结果。这是很强的确定性信息，但不是抽牌泄漏。若后续加入“发现未知牌/随机环境”，预览应只展示候选池或概率，不应把 RNG 结果提前算给 UI。
- `tests/combat.test.js` 的模拟器枚举候选时直接调用 `applyAction`，因此拿到了包含未来手牌的完整 outcome；当前评分只读 events，没有利用隐藏牌序，但测试结构允许以后无意作弊。`tests/helpers/adventure-policy.js` 使用 `previewAction`，边界更合适。

## 现有平衡测试的证明边界

- 相关 48 项纯 JS 测试全部通过，只证明内容数量/契约、resolver 路径、存档和若干规则正确。
- “74 张牌均通过 resolver”把每张高费牌预先设为 3 层蓄能，把条件牌预先设为第 3 张，刻意绕开了自然可达性。
- “三个区域三难度完整结算”使用 `forcedWin` 把敌人生命改为 1，不是难度或经济验证。
- 两个胜率测试只覆盖黄昏邮街普通难度、3 个 seed；复杂起手只覆盖同一队伍。其策略逐动作最大化即时伤害/灼烧/标记，防御权重很低，奖励只按 `(伤害 + 灼烧×2) / cost`，完全忽略虚弱、护盾、治疗、抽牌、蓄能、环境与机会价值。不能拿 3/3 胜利来证明卡组平衡。
- 当前“零费不会无限循环”的结构断言和单卡测试没有组合搜索；需要一个有界状态空间探针覆盖 16 张最大牌组、两件遗物、三个被动、重复 0 费奖励和洗牌回环。

## 优先修正建议

1. 先定费用基准再改牌：以 `strike=1费6伤`、`guard=1费6盾` 为基线，为抽牌、能量、全体、延迟、无视护盾和保留建立明确折价。把 1 费三效果套餐拆开；让 2 费成为真正的复合牌层，3 费成为可直接支付的强牌层。
2. 修正高费的支付方式，三选一即可：保留 3 能量重置时把终结降到 3 费；或回合结束把未用能量自动转成蓄能；或复杂起手每战可靠地产生基础蓄能。最简洁的是“未用能量转蓄能，上限 2/3”，让等待成为玩家选择，而不是抽到指定发动机的许可检查。
3. 让每张蓄能牌和终结牌单独可用，并让奖励成套：消费者在 0 蓄能也有合理 3 费基础效果，蓄能解锁额外段；奖励提供“源/消费者二选一”或根据牌组缺口配对，避免死资源。
4. 重做 0 费身份：保留少量免费数值牌，其余改为一次性的规则动作，例如改写下一次敌方意图、把一种状态转换为另一种、查看牌顶 2 张并选择顺序、发现 3 张临时牌选 1、切换本回合环境。发现结果在确认后生成，预览只显示池与概率。所有会抽牌/产能/生成 0 费牌的 0 费动作保持消耗或每回合一次。
5. 清理明确支配：优先处理 `sunset-glow/wax-impression`、`nav-compass/blanket-quilt`、`orangecat-sidestep/ticket-cut`、`address-label/firefly-flash`、`quiet-bell/soup-steam`。差异应来自条件、目标、时点或副作用，不只是同费多送一个效果。
6. 给弱起手一个出口：营地允许升级或变形/移除一张基础牌；否则不要把 starter 设计成显著弱牌。牌组上限 16 时，每次删牌都应是清楚且有限的选择。
7. 重画三区曲线：桥、市普通怪不要低于首区后再让精英/Boss陡升；按总有效生命、每轮期望伤害、召唤额外生命和状态清除一起预算。高难护甲若保留，应给多段/低伤和灼烧之外的反制。
8. 换掉胜率证明：建立费用审计表、首用 Pareto 检查、source/sink 成套率、高费第 N 回合可达率、0 费组合有界搜索；再用多种策略（防御、状态、连锁）跨 3 区×3 难度×足量 seed 输出分布。胜率只能作为结果指标，不能代替费用和决策质量检查。
