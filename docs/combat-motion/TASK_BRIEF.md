# 纸灵驿使 · 战斗动作图片扩展

用户于2026-09-10要求“调用luna批量生成角色和boss的每回合行动画面，包括出场、攻击、防御、受伤、退场、受控、buff、debuff等状态的图片，并补充在战斗中的互动中”，并指定“用 luna max”。执行模型采用 gpt-5.6-luna / max，调用内置 imagegen 制作图片；root负责接入与验收。

## 已确定范围

沿用此前用户已确认的纸灵驿使风格与22位伙伴身份，3位Boss各两个阶段。共28个身份/阶段，每个8种动作，目标224张状态画面；角色ID、规则数值与存档不改。现有普通敌人仍接收通用反馈，新增独立动作画面优先覆盖用户指定的伙伴和Boss。

每个身份先生成一份统一机位的4列2行动作精灵母稿，再拆成8张图片。顺序严格为：

第一行 enter 出场、attack 攻击/施法、guard 防御、hurt 受伤。
第二行 exit 退场、control 受控、buff 增益、debuff 减益。

这些是实际游戏素材，不是带字说明海报。读者应能在小屏上直接识别谁在行动、受到何种影响、效果来自谁。每个状态改变姿态或主要动作，不以8张换色待机代替。

## 图像约束

- 原角色/对应Boss阶段的现有PNG为身份参考，保留脸、肢体数量、服装结构与标志性工具；先用view_image查看引用图，再用内置imagegen。
- 真透明背景PNG，无棋盘格、无标签、无网格线、无底座、无文字、无其他人物。4列2行均匀排布，每格同样大小，主体及特效完整留在自身格内，四周留10%空隙，尺寸比例/基线一致。
- 纸折面、纸纤维、少量铜/绳细节，柔和2.5D插画。光从左上，不转成毛绒/塑料公仔。
- enter：踏出或展开纸信的迎战姿态；attack：清晰向右挥击/施法；guard：工具或信盾护在身前；hurt：收身后仰和少量纸屑。
- exit：低身、收拢、散出少量纸片，保留可辨脸/主体，适合暂时倒下；control：靛蓝纸丝/约束符围住脚或工具，脸保持可见；buff：振作姿态配暖金/青绿色纸羽；debuff：低落姿态配冷灰墨纹/负面符号，和受控区别明显。无血腥。
- 四足、悬浮或非人形按参考自身结构动作，不能强行加人类手脚。无新增肢体，无断裂工具或跨格串影。
- 高分辨率母稿、最终提示词、实际路径保存在本项目 docs/combat-motion；不要覆盖此前素材。

## 运行与验证

先实测格式及包体，再确定运行图片尺寸；不靠远程图片服务。每个战斗分包使用自己包内的动作资源，主包保持目标1.7MiB，每分包低于1.9MiB。原始PNG始终保留。图像生成完成后由root做分割、透明/边界检查和运行资源接入。

受控画面对应已有虚弱等受制状态，不擅自新增眩晕/跳过回合规则。buff/debuff与现有counter/echo/retainBlock、mark/burn等状态对应；每次动作提交后生成表现，动画不负责结算，不重复发奖。退出/后台保持可续玩。

只在获准的隔离副本做消费/战斗；不注入fixture、余额或RNG。CLI控制台使用 --command 'grep -i error'，必要时 --command 'grep -n .'，SDK SystemError/routeDone原文单列。截图日志先系统临时目录再归档，不把模拟器结果外推真机。

## 首批技术修订

首批内置生图将“透明”画成棋盘格，且大幅攻击特效触及相邻格。后续母稿统一使用纯色洋红 #FF00FF 底（无棋盘、无渐变、无阴影底板），由root统一用本机管线转为透明运行PNG。Luna不得自行删除角色或截断跨格特效，不做中性颜色全图抠图。每格主体连同特效最多占格子宽高的70%，保持20%左右安全留白；攻击可用斜向动作，小范围纸光弧，不做横跨整格的超大扫光。八种姿态仍需明显不同。原有透明性约束作用于最终运行图，母稿的洋红底属于生产中间格式。

## 分包方案实测修订

192像素/96色PNG的首批小鸭8帧共89661字节，复制22位到三个地区会超出1.9MiB阈值。伙伴动作改放三个公共素材分包，使用微信官方分包异步化自定义组件引用，组件只读自己所属包的图片；主包占位组件保留原伙伴肖像。出发/续玩先加载本队所需素材包，失败保留已创建的远行。Boss动作留在对应地区分包。原背景质量不因此降低，运行PNG优先256像素/128色，按实际总量核验后收敛。

官方依据：https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/async.html 。最低基础库2.11.2，当前项目既有getWindowInfo已经要求更高版本。WebView的webp属性仅明确支持网络资源，因此本轮离线资源选择PNG。

实际小程序运行时验证wx.loadSubPackage与wx.loadSubpackage均不存在，准备素材改用官方require.async调用固定包入口（同一入口的组标识也由包内组件使用），不引入兼容回退。
