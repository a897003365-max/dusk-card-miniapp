## 实际实现与复制清单

- 本次没有复制上述三个仓库的代码片段、数据文件、音效、图片、字体、角色名称或商业美术，复制片段清单为空。
- `utils/combat-content.js` 的 22 个被动、62 张牌、18 件遗物、21 个敌人及三个区域按本项目的 [CONTRACT.md](CONTRACT.md) 编写；卡牌说明直接由本项目效果数组生成，升级效果完整替代基础数组。
- 本地战斗逻辑采用为原生微信小程序新写的 JavaScript；开源项目用于机制与结构研究，未作为 npm、Godot 或运行时依赖接入。
- 保留的 22 个公仔身份与 88 张收藏图片来自用户原有项目，来源见 [素材来源.md](../素材来源.md)。本文件不为这些本地图片另行推断开源许可证；本轮新增敌人及卡牌文案为本项目原创。
- LICENSE 记录仅描述各仓库该版本的根许可；不把根许可外推为第三方依赖、品牌或关联游戏商业素材的许可。若后续确实复制代码或素材，必须补上原路径、固定 SHA、目标路径、具体范围及随附许可，不得把当前的“未复制”记录继续沿用。

## 可复核的官方 API

对每个上述仓库，以以下三个只读端点完成固定：

1. `GET https://api.github.com/repos/{owner}/{repo}`，读取 `default_branch`。
2. `GET https://api.github.com/repos/{owner}/{repo}/commits/{default_branch}`，读取 `sha` 与提交时间。
3. `GET https://api.github.com/repos/{owner}/{repo}/license?ref={sha}` 及 `/readme?ref={sha}`，核验固定版本的许可与公开项目说明。

本轮未打开或复制 Slay the Web 的 AGPL 业务源文件，也没有把其说明逐句翻译进项目。上表保留的是来源索引与研究结论。
