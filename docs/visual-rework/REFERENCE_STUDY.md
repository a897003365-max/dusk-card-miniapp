## 2. 亲眼观察到的炉石节奏

以下时间是对官方 GIF 的粗分段，约有 2 秒抽样粒度，不是游戏参数。

| 演示时间约段 | 看到的画面 | 可借鉴的关系 |
| --- | --- | --- |
| 0–8 秒 | 包堆被聚拢，中央圆形区域亮起，数量变化 | 玩家动作先得到可见回应，结果尚未出现 |
| 8–14 秒 | 聚合物进入中心，光圈增强，卡包向外展开 | 把能量收拢和释放做成两个不同方向 |
| 14–18 秒 | 多张卡背排列并停留，随后翻出牌面 | 爆发之后留出玩家决定揭晓的空间 |
| 18–24 秒 | 亮点牌面可查看，随后出现分类汇总 | 高潮结束后尽快恢复清晰、可读的结果 |

对《晚霞来信》的推论是：**开封动作、稀有度预示、伙伴登场、结果阅读应该是不同职责的阶段。** 动画层数和持续时间不能替代这条因果。批量开启仍应保留逐封体验与快速查看两条明确操作。以上流程来自[官方演示及说明](https://hearthstone.blizzard.com/en-us/news/23999067/introducing-mass-pack-opening-the-new-way-to-open-your-pre-purchase-bundles)。

## 3. 阴阳师可借鉴到什么程度

可以据官方材料采用两个原则：高稀有角色拥有自身的登场语境；十连中的高稀有结果必须及时、明确地反馈。鲸汐千姬发布文案把召唤与该角色的海域、行动动机和自述连接，适合启发本项目用“这位邮路伙伴做了什么”完成登场，而不是所有角色套同一个光圈。[官方角色发布页](https://www.bilibili.com/video/BV1Km411X7Vt/)、[官方更新说明](https://en.onmyojigame.com/news/official/20190923/27314_834134.html)。

本轮**不能**把“画符几秒、镜头如何推近、SSR/SP 怎样变色、何时播角色语音”写成亲眼观察结论。也不把阴阳师的 SP/SSR 分级机械映射为本项目 UR/SSR。下面四档时长与动作均为本项目设计建议。

## 4. 四档演出建议

共同对象使用晚霞邮局自己的信封、封缄、邮路灯与新设计伙伴。配色是暂定语义色，最终材质随新公仔方向统一；不能只把同一动画换四种颜色。

| 档位 | 预示 | 释放与角色动作 | 稳定结果 | 建议自动段总长 |
| --- | --- | --- | --- | --- |
| **R：平信到访** | 封缄轻压，暖白细光沿封口走过 | 封口直接展开，伙伴短距离落定，单次轻回弹 | 朴素邮票边框、明确 R 标签；主体马上可读 | 0.6–0.8 秒 |
| **SR：急件亮灯** | 青绿双线沿封缄绕行，邮路小灯逐个点亮 | 两侧纸页展开，少量纸屑外散；伙伴做一次职业动作 | 双层边框与局部灯光，保留 SR 标签 | 1.0–1.2 秒 |
| **SSR：星邮开门** | 场景压暗一档，紫色封印出现裂光，短暂停顿 | 一道纵向纸门打开，主体从门后向前；背光展开后立即收束 | 更大的角色、独有剪影动作、SSR 印记；背景退为陪衬 | 1.6–1.9 秒 |
| **UR：远方回信** | 金白核心与深色剪影先后出现，封缄悬起；停顿比 SSR 明确 | 前后两层邮路景片错位打开，伙伴完成专属入场动作；一次宽光环扩散，随后还原正常明度 | 最大但不裁切的角色；独有边框结构、UR 印记及一处缓慢局部动态 | 2.3–2.7 秒 |

这里的“定格”是可持续阅读的稳定状态，不是又一段必须等完的计时。稀有度标签、伙伴名、新伙伴/新形态/重复结果必须一直可读。金色作为明确稀有预示有[炉石官方文字依据](https://hearthstone.blizzard.com/en-gb/news/20852959)，但本表的邮路意象、颜色组合、动作和时长全部重新设计。

### 让新公仔与娃娃机公仔拉开距离

登场时先用一眼可辨的职业剪影，再露出表情和细节。新的头身比、眼型、肢体比例、服装结构和代表性工具应参与这个动作。只给旧圆脸绒团换配色、戴帽子、套金边，无法完成本轮重构。最终画面不能模仿现成式神动作、炉石卡背或经典角色姿势；旧 A / B / C 保留为历史探索，不作为当前批准方向。

## 5. 原生 WXSS 与位图的实现落点

优先复用项目已采用的 `image` 分层及 WXSS `transform / opacity / @keyframes`，把精细绘画交给原创位图，把位移、缩放、遮挡与显隐交给界面。不要用几十个 CSS 小块拼公仔。

| 层 | 内容 | 运动方式 |
| --- | --- | --- |
| 场景底层 | 安静的邮路环境或纸面 | 轻微缩放/明度遮罩，避免持续漂移 |
| 封缄与前景 | 独立透明封缄、左右纸页 | 以封口为轴旋转或平移，运动后让出角色 |
| 角色主体 | 透明主立绘；SSR/UR 可增加一份职业动作姿态 | `translateY + scale`；确实需要换姿态时切换两幅素材，不扭曲脸 |
| 局部光效 | 独立透明光环、裂光或少量纸屑图层 | 单次扩散和透明度衰减；粒子数量固定，不运行无限粒子系统 |
| 结果层 | 原生文字、稀有度标签、来源/重复说明、操作按钮 | 主爆发结束后出现，保持稳定、可选中操作 |

建议使用一个演出阶段值和一份按稀有度定义的时长/层配置，避免为四档建立四套结算逻辑。随机结果与存储应在演出开始前已确定，跳过、关闭和切后台只改变展示，不重新抽取或再次扣邮票。连续点击不能叠加多份演出。详细拆分与资源预算仍需在 320/390/430 原生环境验证，本文不宣称已验证性能。

炉石的 2015 年制作访谈具体说明了遮罩与分层局部动画，并提醒装饰动效不能被误认成玩法状态。可以借鉴“让材质局部活动、主体持续可读”的方法；文中当年的层数上限不是本项目或当前炉石的技术限制。[官方制作访谈](https://hearthstone.blizzard.com/en-gb/news/18053404)。

### 批量与跳过

- 逐封开启：每个真实结果按自身档位演出，用户可决定下一封。
- 全部开启：R/SR 快速并行落定；最多突出展示本批一个真实的最高档结果，其余全部进入清楚的汇总。不要强制串播五段长动画。
- 用户可以随时跳到稳定结果。减弱动效模式用短淡入替代推镜、抖动和粒子，四档仍靠边框结构、标签和主体呈现区别。
- 音效另行原创或使用获准素材；本轮没有分析到可验证官方音轨。避免频繁全屏白闪，结果文字与关闭按钮不随光效消失。

## 6. 后续验收要回答的问题

1. 静音、缩小到 320px 后，四档能否凭动作结构与最终画面区别，而不仅是颜色？
2. SSR/UR 的脸、名称、稀有度和“新/重复”信息是否在高潮后清楚停留？
3. 五封混合结果中，每份内容是否可查、顺序可理解，快速开启能否真正节约时间？
4. 关闭、跳过、切后台、重复点击后，是否仍只扣一次邮票、只入库一次？
5. 正常与减弱动效模式是否都保留至少 44px 的关闭/继续触区，没有被光效遮挡？

本次只完成来源研究与建议，没有改运行代码，没有生成新公仔或动画资产，也没有批准任何美术方向。
