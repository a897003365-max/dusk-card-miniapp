# 冒险验收策略

`adventure-policy.js` 提供 `chooseFromView(view, preview, style)`。策略只拿玩家可见视图和当前动作预览，不能读取抽牌堆顺序或动作后的状态；`chooseAction(state, options)` 仅包装这两个公开入口。`balanced`、`guard`、`status` 是不同取舍的启发式，不是最优玩家或平衡认证。

它考虑当前敌人意图、有效护盾与治疗、负面状态、护卫对象、环境对敌我双方的影响、资源、手牌选择和情境牌改签。发现/观星候选只有在付出后进入视图；换牌结果不会被预先利用。Boss 转阶段不等于消灭一名攻击者，评分单独处理。

运行 `node scripts/benchmark-combat.js --out=/tmp/dusk-combat-benchmark.json` 可复跑四种起手、不同队伍/策略及地区对照。区域解锁、伙伴拥有与等级是明确的实验初始条件，战斗过程中没有注入牌序、生命、余额或伤害。报告中的4费可支付占比按“持有该牌的回合”统计，不是抽到该牌的概率，也不是所有高费永远不能打出的比例。

Node基准不能代替真人时长、构筑偏好或微信原生验收。真实UI验收通过 `native-adventure.js` 对专属KEY临时副本执行点击；`chooseOpportunity` 和 `tradeCard` 同样必须映射为真实可见按钮。所有截图与结果先在系统临时目录写入，再归档。
